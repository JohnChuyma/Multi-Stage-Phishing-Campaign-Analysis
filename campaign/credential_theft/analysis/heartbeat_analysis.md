# Heartbeat Tracking
## Overview
During analysis of the phishing infrastructure hosted on `vguvi.vu`, a recurring request was identified to: `/google/rsvp/update_online.php`
The request was generated automatically by client-side JavaScript and executed repeatedly while the phishing pages remained open.
This behavior indicates that the phishing application actively monitored victim sessions throughout the authentication workflow.

---

## Observed Request
```http
GET /google/rsvp/update_online.php?session_id=<redacted>
```
Response:
```http
HTTP/2 200 OK
```
### Key Observations
- The endpoint was accessed using the HTTP `GET` method.
- The server responded successfully with `200 OK`.
- Requests contained a victim-specific session identifier.
- PHP session management was active through `PHPSESSID`.
- Traffic originated from pages within the phishing workflow.
- Requests were routed through Cloudflare infrastructure.

## Request Origin
Observed request headers showed the request originated from: 
```text
Referer: pages/login.php
```
Additional header:
```text
sec-fetch-site: same-origin
```
These values confirm that the request was generated by the phishing site's own pages rather than by an external website.

---

## Source Code Evidence The login page contained the following JavaScript: 
```javascript
setInterval(function() {  fetch('../update_online.php?session_id=<redacted>');}, 3000);
```
The script executes every three seconds while the page remains active.

---

## Behavioral Analysis
The observed request pattern is consistent with a heartbeat mechanism used to monitor active victims.
Characteristics include:
- Automatic execution without user interaction.
- Continuous communication with the backend.
- Tracking tied to a unique session identifier.
- Fixed execution interval of three seconds.
- Persistent activity while phishing pages remain open.
- The combination of PHP session management and a recurring heartbeat endpoint allows activity to be associated with a specific victim session.
- This functionality provides visibility into whether a victim is currently interacting with the phishing pages and where they are within the authentication workflow.

---

## Security Assessment
Evidence indicates that `update_online.php` functioned as a session-monitoring endpoint.
When combined with:
- Credential collection through `password.php`  
- PHP session tracking  
- Staged redirects between phishing pages  
- A fake Google verification workflow  

The heartbeat mechanism suggests that attackers were capable of monitoring victim activity in near real time.
The presence of active session monitoring supports the assessment that the phishing kit was designed to coordinate the user experience with attacker-driven authentication attempts against legitimate Google accounts.

---

## Conclusion
Analysis confirmed that `update_online.php` served as an active heartbeat endpoint within the phishing workflow. The endpoint received recurring requests tied to individual victim sessions and provided a mechanism for tracking user activity throughout the staged authentication process.108 109This behavior is consistent with sophisticated phishing kits that monitor victim progress and synchronize attacker actions with credential-harvesting operations.
